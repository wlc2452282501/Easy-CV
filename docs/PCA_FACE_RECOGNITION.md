# OpenCV / PCA 人脸识别

首页进入 **OpenCV 工作台 → PCA 人脸识别**。原来的节点流程在同一入口的第二个标签页。
页面布局位于 `ui/facerecognitionpage.ui` 和 `ui/opencvpage.ui`，可以用 Qt Designer 编辑。
业务代码位于 `app/facerecognitionpage.*`；算法位于 `core/pcafacerecognizer.*`。

## 对应课程要求

| 要求 | 实现 |
| --- | --- |
| C++ 可视化系统 | Qt Widgets / Designer 表单，OpenCV C++ 算法 |
| 比对至少 10 个不同用户 | 姓名/学号为人员标签；有效人员少于 10 人禁止训练；识别列表展示全体人员的距离排名，没有 10 人上限 |
| 预处理 / 直方图归一化 | 灰度化、可选 Haar 单人检测裁剪、100×100 缩放、`cv::equalizeHist` 全局直方图均衡化 |
| PCA 特征提取 | `cv::PCA`，默认保留 95% 方差，可手动指定主成分数；显示实际维数、保留方差、平均脸和特征脸 |
| 识别 | 查询图像使用相同预处理和训练得到的 PCA；按每位人员最近样本的投影距离排名，并用阈值拒识 |

## 准备真实数据

项目已从剑桥大学官方存档整理 **ORL / AT&T 数据集：40 人、400 张照片**。
直接选择默认“已裁剪的单人人脸”模式，导入 `data/att_faces/train`（280 张），
用 `data/att_faces/validation`（40 张）调节参数，再用 `data/att_faces/test`（80 张）评估。
来源、署名、预览和完整文件清单见 [数据集说明](../data/att_faces/README.md)。
自动化测试中的人工纹理仅检验算法流程，不能作为人脸识别效果的证明。
也可以自行准备单人正面照片，按下面的通用结构导入。

```text
faces_train/
  001_张三/
    01.pgm
    02.pgm
    ...
  002_李四/
    01.jpg
    ...
  ...
  010_王五/
    01.png
    ...

faces_test/
  001_张三/
    test_01.pgm
  002_李四/
    test_01.jpg
  ...
  010_王五/
    test_01.png
  未登记人员A/
    test_01.jpg
```

每个根目录下的一级子目录代表一个人，同一人的训练和测试目录名必须完全一致。
支持 PNG、JPG/JPEG、BMP、PGM、TIF/TIFF、WebP，扩展名不区分大小写。
建议至少 10 人，每人 5～8 张用于训练，另留 2～3 张独立照片用于评估。
不同人员必须使用不同名称，相同名称会被当作同一个人。
空目录、无法解码的照片、预处理失败的照片不计入有效人数，原因显示在日志中。

如果照片已经是裁剪好的单人人脸，使用默认模式，无需额外模型文件。
普通场景照片应先选择 Haar 模式，再选择 OpenCV 提供的
`haarcascade_frontalface_default.xml`（通常在 `/usr/local/share/opencv4/haarcascades/`
或 `/usr/share/opencv4/haarcascades/`）。系统也会尝试自动查找这些位置。
普通照片必须恰好检测到一张人脸；没有人脸或存在多张人脸时会明确报错，不会默默把背景当作人脸。

## 操作流程

1. 先选择预处理模式，再点击“导入人员库目录”。该操作成功后替换当前内存中的人员库。
2. 或使用“录入 / 追加人员照片”，输入姓名/学号并多选照片。相同人员名追加样本，重复路径跳过。
3. 检查人员列表与有效人数。至少 10 人时“训练 PCA 模型”可用。
4. 主成分数默认自动保留 95% 方差；手动值会限制在 `min(样本数-1, 10000)` 内。
5. 训练完成后查看平均脸和不同主成分的特征脸；实际维数可能小于所填写的数值。
6. 在“识别与逐人比对”载入一张待识别照片，点击“开始识别”。页面显示预处理图、PCA 重建、最近候选样本与所有人员排名。
7. 在“独立测试集评估”选择测试目录，可导出包含真实标签、结果、距离、判定、阈值及实际 PCA 维数的 UTF-8 CSV。

导入、训练和批量评估通过 Qt Concurrent 在后台执行。当前数据与模型仅保存在内存中，
关闭程序后需重新导入和训练；移除人员不会删除磁盘上的照片。
修改预处理设置会清空当前内存数据，避免混用不同预处理的样本。
修改人员库或主成分数会使模型失效，修改阈值会清除旧识别及评估结果。

## 算法与距离

训练样本均衡化后展开为 `N × 10000` 的浮点矩阵 `X`，每行对应一张人脸。
PCA 只在训练集拟合平均向量 `μ` 和主成分矩阵 `W`，得到投影 `Z = (X - μ) Wᵀ`。
查询也使用训练得到的 `μ` 和 `W`，不重新拟合 PCA。

每位人员的距离是其全部训练样本中最小的
`||z_query - z_sample||₂ / sqrt(10000)`，按距离从小到大排名。
若最近距离不超过阈值则接受该人员，否则输出“未知人员（拒识）”。
距离不是置信概率，默认阈值 45 只是起点；应在独立验证集上调参，再在测试集报告结果。
PCA 投影可能忽略未知人员的某些差异，距离阈值不能保证拒绝所有未登记人员。
PCA 适合姿态、裁剪和光照较一致的正面照片；Haar 裁剪不包含眼睛关键点对齐。
实际准确率由真实数据决定，系统不会宣称固定准确率。

评估分别统计已知人员的正确识别率（含拒识导致的失败）和未知人员的正确拒识率。
系统排除与训练照片路径相同、或预处理后像素完全相同的测试图片。
近似重复、重编码及同次连拍仍需人工划分，不能只靠程序排除数据泄漏。
没有有效测试图片时不显示虚假的 0% 或 100% 准确率。

## 构建与测试

目标环境维持 Qt 5.12.4 / qmake / Ubuntu 22.04；新增 Qt Concurrent，
PCA 使用现有的 `opencv_core`，检测使用现有的 `opencv_objdetect`，无需另装深度学习模型。

```bash
qmake VisionPlatform.pro
make -j"$(nproc)"
./VisionPlatform

# 在项目根目录执行，测试构建与主工程隔离
mkdir -p .build/face-tests
cd .build/face-tests
qmake ../../tests/face_recognition_tests.pro
make -j"$(nproc)"
QT_QPA_PLATFORM=offscreen ./face_recognition_tests
```

测试覆盖直方图均衡化、无效图像、中文路径与损坏图像、至少 10 位独立标签、
PCA 与逐人排名、阈值拒识、主成分数限制、失败训练的状态保护和 OpenCV 页面导航。
另有通过真实文件选择框操作的导入、后台训练、查询、评估、重复样本排除与 CSV 导出全流程测试。

本次已在 Windows 本机使用 Qt 5.15.2 和 Qt 6.7.2，分别结合 OpenCV 4.11.0 完成编译与测试。
两套环境各通过 11 项检查（含测试初始化和清理）。Ubuntu / Qt 5.12.4 的实际构建仍需在目标虚拟机执行上述命令。
这些检查使用人工纹理验证数据流，不代表真实人脸测试准确率。
